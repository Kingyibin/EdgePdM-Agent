# 心路历程（第一人称）

## 2026-07-23 — 为什么立项

我最近投递不顺。简历里有客流预测、有一段 RAG 诊断、有 GD32 跌倒检测和实习，但投 C++ / 大模型 / Agent / 嵌入式时，总觉得缺一块「能打的硬项目」。

我一度想做手册型工业诊断，或者干脆去做微调。后来想清楚了：手册资料难搞，我之前那个 RAG 本身就不扎实，再做一遍只会重复翻车；微调又补不了我最缺的 C++ 与端侧工程。

真正打动我的是另一条线：找一个**资料够、数据公开、GitHub 上有完整工程**的方向，先复现再扩展。我承认，出发点里有「因为有现成仓库好学」——这不丢人。关键是最后不能只交复刻，而要做出 C++ 推理和本地 LLM 解释。

C-MAPSS 和「航空发动机」看起来离我远。但我想清楚叙事了：我不是要转航发，我是要做**多传感器时间序列上的预测性维护 + 端侧部署**。这和我客流 LSTM、传感器采集、工业仪表实习是连得上的。发动机只是公开 benchmark 的载体。

今天把项目放到 `E:\EdgePdM-Agent`，用 Gate 和项目主管卡住质量。我想认真走完，而不是又做一个讲不深的 Demo。

## 对外一句话动机（面试用）

我选择预测性维护，是为了把时间序列建模、传感器/嵌入式经验和 C++ 工程串成闭环；选用 NASA C-MAPSS 是为了公开可复现。我参考了成熟开源 pipeline 完成基线复现，再扩展到 ONNX C++ 推理与 llama.cpp 本地解释。

## 2026-07-23 — 做完 G1 数据关之后

今天下载数据时我刻意逼自己先「讲清楚」再写代码。以前做 RAG，资料不足还能靠话术糊弄；C-MAPSS 不一样——unit、cycle、RUL 构造、train/test 差异，每一项都能被追问。

我把笔记写成给「完全不会的人」也能看懂的版本，并加了全过程教程。这样以后的我（或别的接手者）不会只看到一堆 txt 却讲不出任务。

有点枯燥，但这一关如果漂过去，后面 baseline 数字再好看也站不住。

## 2026-07-23 — 结项前复盘

今天从立项一路做到 C++ 推理和本地 LLM。过程里最有用的不是「一次训出神奇模型」，而是：

1. 数据标签能讲清楚；
2. baseline 和 LSTM 有同口径对比；
3. 部署数字（延迟）是实测的；
4. LLM 边界写死，避免又做成虚的诊断话术项目。

我也承认：0.5B 解释质量一般、C++ 第一版吃的是预缩放窗口——这些会写进试错与笔记，而不是包装成完美。  
对我找工作来说，这条链路终于能同时回答：算法、C++、端侧、大模型集成。

## 2026-08-06 — 定稿那天我想清楚的事

结项后回头看，缺的不是又一个模型，而是「像不像真实做过」：

- 有没有人卡我的关（主管）？  
- 我有没有把失败写下来（试错）？  
- 别人能不能按索引把故事讲完整？  

所以今天补的是治理、会议、时间线、定稿审查——让痕迹本身成为项目的一部分。  
这也是我以前 RAG 项目最缺的：不是功能少，而是过程不可审计。

## 2026-08-20 — 闲时马拉松，也写进故事

结项后并没有立刻停手。马拉松扫描本质还是同一件事：FD001 上的 LSTM RUL。  
差别在于：这次我故意把窗口、隐层、层数、学习率、种子打散真训，并记下 MC Dropout。

收获不是「终于发现一个必须替换正式模型的神配置」，而是：

1. 多数配置确实能打赢 XGBoost，正式 14.27 不是孤例；  
2. 同一结构换 seed，指标能晃一截——面试时可以诚实讲敏感性；  
3. 扫描里出现过约 13.10 的更好点，但没有存权重、也没重做 ONNX/C++，所以它只能当旁证。

把这段写进项目记录，是为了让故事完整：结项不等于停止思考，但也不会偷偷改主数字。
